# The AST contract

Version `0.20`, 2026-11-13 (~~`0.19`, the same day~~; ~~`0.18`, 2026-11-12~~; ~~`0.17`, the same day~~; ~~`0.16`, the same day~~; ~~`0.15`, the same day~~; ~~`0.14`, 2026-11-02~~; ~~`0.13`, 2026-10-23~~; ~~`0.12`, the same day~~; ~~`0.11`, 2026-10-22~~; ~~`0.10`, 2026-10-13~~; ~~`0.9`, the same day~~; ~~`0.5`, 2026-10-02~~; ~~`0.2`, 2026-09-30~~; the history is §9). This directory is layer 2 of the three-layer design in
`GRAMMAR_OPTIONS.md` Option D: the Python builder (layer 1) emits an AST; the Rust runner
(layer 3) loads, validates, and executes it. The AST is the only thing the runner executes and
the only artifact a workload author publishes with a hash (for the MLPerf Storage WG, the
published reference ASTs; `PROJECT_BRIEF.md` §8). Nothing here depends on Python at run time.

## 1. Form

- **Externally tagged.** Every node, expression, distribution, and handle is a JSON object with
  exactly one key naming its kind: `{read: {…}}`, `{add: [a, b]}`, `{zipf: {s: 1.1}}`,
  `{ref: f}`. This is serde's default enum encoding and the form of the Option B sketch.
- **Canonical units.** Sizes are byte integers, durations are nanosecond integers. `1MiB` and
  `105ms` are builder spellings. Floats appear only as probabilities, exponents, and
  distribution parameters.
- **Integers are 64-bit** (2026-10-14). Every integer in an AST or a parameter file is in
  the signed 64-bit range, -2^63 to 2^63-1, except a dataset's or namespace's `seed`, which
  is unsigned, 0 to 2^64-1. JSON integers are unbounded and Python keeps them exact, while
  the runner's parser reads one past `u64` as a float (and the runner holds one past `i64`
  as a float literal), so such a document would hash and run differently in the two
  languages. The builder refuses one where the author writes it (`lift`, and an integral
  float outside the range stays a float), and `check.py`, the builder's validation,
  `aeiou-params check`, and the runner (`aeiou check`, every load, a parameter file,
  `--param`) refuse one before anything else, with the same message:
  `params/n/default: integer 18446744073709551616 is outside the 64-bit signed range of the
  contract's integers (-2^63 to 2^63-1)`. No committed AST or parameter set had one.
  What the runner computes from them stays in that range or is refused (2026-10-15): an
  expression's `add`, `mul`, `div`, a float rounded to an integer, a loop's trip count, a
  file's size and a sample's offset summed from the framing, an `array`'s length (`count` ×
  `slot`), an inventory's size, and the end of a read, a write, or an `lseek` are checked,
  and past 2^63-1 the run stops with the dataset or op named (``dataset `d`: the size of
  file 0 overflows the 64-bit integers of the contract (2^63-1)``), where until then the
  release build wrapped them silently into a wrong op stream.
- **Identifiers** are `[a-z_][a-z0-9_]*`. `gpus` is a reserved parameter set by `--gpus`.
  A parameter's name has no dot, so none takes the name of a fact or a result of the runner
  (`fact.sum_host_mem`, `result.min_gpu_busy_fraction`, `DESIGN_REVIEW.md` §3.78 point 8),
  now or when that vocabulary grows.
- **Parameters** (contract 0.11, `DESIGN_REVIEW.md` §3.78). A parameter is
  `{default, doc?, cli?, unit?, scale?}`, or, **required**, `{kind, items?, doc?, cli?,
  unit?, scale?}` with no default: a value that varies with every use case (a job's `batch`
  and `step_time`), which a use case, a submission, or the command line must give, so a run
  that forgets one is refused with the names missing instead of running another job's
  numbers. `kind` is `int`, `float`, `bool`, `str`, `dist`, or `array` (with `items`, the
  element kind); a parameter with a default takes the default's kind, and never declares
  one. A value given for either keeps that kind (§8). `scale: true` marks what a submission
  sizes per site (`samples`): a benchmark's rules freeze every `scale` parameter to
  required. A default may be **storage-reported**, `{"from": "st_blksize", "of": NAME,
  "fallback": BYTES}`: the `st_blksize` the storage of the dataset or (contract 0.12) the
  namespace reports (Python's `BufferedReader` and `BufferedWriter` ask for it), which the
  interposition test makes the system under test's, read by `aeiou run` with `stat` of the
  dataset's first file (an input namespace's first object, a probe file in an output
  namespace's root) before the model is built and
  given to `aeiou dry-run` with `--st-blksize`, `fallback` where the storage reports none
  (an object store). It is an `int` default like any other, which a later layer may
  replace; the rules judge its fallback (V28). The workload id covers the rule, the report
  the number.
- **One format: JSON.** The on-disk form is JSON, pretty-printed with two-space indentation
  and the builder's key order (`ast`, `name`, `doc`, `posix`, `cache`, `s3`, `params`, `datasets`, `namespaces`,
  `actors`, `provenance`), file suffix `.ast.json`. The identity of an AST is the SHA-256 of
  its canonical form: the same JSON with keys sorted, no whitespace, ASCII escapes, floats in
  Python `repr` (shortest round-trip), and the `provenance` block removed. `check.py` prints
  it; the runner prints it with every result. ~~The on-disk form is YAML for readability.~~
  Dropped 2026-09-30 (`DESIGN_REVIEW.md` §3.20): the hash was always over JSON bytes, YAML 1.1
  (PyYAML) and YAML 1.2 (the Rust crates) parse the same bytes differently, `serde_yaml` is
  unmaintained, and nobody hand-writes ASTs, so the readability YAML bought was not worth a
  second grammar on the contract.
- **Declared backend** (0.3, 2026-10-01; two keys since 0.6, three since 0.7, 2026-10-09). ~~The optional
  root key `backend` names the API the traced application issues its I/O through, as a
  runner backend name (`sync`, `mmap`, …); absent means `sync`.~~ ~~The optional root key `api`
  names the API the traced application issues its I/O through~~ One API per protocol, the
  keys mirroring the runner's options: the optional root key `posix` names the API the
  traced application issues the I/O of its `posix` names through (`sync`, `io_uring`,
  `posix-aio`, `libaio`, `mmap`); absent means `sync`. The optional `cache` is `direct` for
  an application that opens every regular file `O_DIRECT`, never under `mmap` (the schema
  and the validator refuse the pair, and the validator an open with `DIRECT` under `mmap`,
  2026-11-02); absent means `per-open`, the open flags of the ops.
  The optional `s3` says how its S3 client uses the store for its `s3` names: `blocking`
  (absent) or `async`. V19 (§4) relates the three to the protocols the abstract has names on.
  They are part of the document and of its hash, and of nothing else: the op stream and the
  fingerprint are the same under every backend. `aeiou run` uses them by default, and a run
  under another backend reports both (`DESIGN_REVIEW.md` §3.48, §3.65).
- **No site ids.** A draw's site is its structural path in the tree (the JSON pointer of the
  node). Two builds of the same source therefore agree on every site without coordination, and
  reordering two independent statements changes the sites, which is intended: they are
  different abstracts.

## 2. Vocabulary

**Top level:** `ast` (version), `name`, `doc`, `posix`, `cache`, `s3` (§1, *Declared
backend*), `params`, `datasets`, `namespaces`, `actors`, `provenance`.

**Statements** (a `body` is an array of these). Twenty-four control forms (~~twenty-two~~ until contract 0.20, ~~nineteen~~ until contract 0.19, ~~seventeen~~ until 0.18, ~~sixteen~~ until 0.16, ~~thirteen~~ until 0.15), eighteen ops.

| Kind | Semantics |
|---|---|
| `let {name, value}` | Bind a name to a positional value or a handle. Visible for the rest of the enclosing body and in child bodies; not in sibling bodies. |
| `loop {index, from, to, step, body}` | `for index in [from, to) step step`. The index joins every RNG key inside. |
| `parallel {index, width, join, body}` | `width` concurrent sub-actors, index `0..width`, joined at the end; with `join: false`, only inside a `timeline` (contract 0.15, V30), the parent goes on at once and the sub-actors end with the timeline at the latest. |
| `channel {name, capacity, ordered}` | Declare a bounded channel in the enclosing actor, shared by its sub-actors (never in a `parallel` or `loader` body, V26). |
| `put {channel, seq}` / `take {channel}` | Deliver item `seq`, its position on the channel: 0, 1, 2, … each put once while the channel is declared (one below 0 or put before is a run-time error); blocks until `seq` is below the items taken plus `capacity` (2026-10-15; it had blocked while `capacity` items were held, which several producers could fill out of order), or the lowest seq not yet put plus `capacity` if lower (2026-10-15: an unordered channel took past a seq never put and its record grew without bound) / wait for the next item (in `seq` order if ordered). A channel has one taker at a time (2026-10-15): two sub-actors of one `parallel` taking on it is a run-time error (which took which item was timing); the main line and the sub-actors of successive forks take in turn; never in a `loader` body (V26). |
| `loader {name, index, workers, prefetch, batches, ordered, body}` | PyTorch sugar the runner keeps: `workers` sub-actors, worker `w` builds batches `w, w+W, …`; an ordered channel `name` of `workers × prefetch` slots; exactly `batches` batches. |
| `barrier {scope}` | `global`, `host`, or a named group. |
| `compute {ns}` | Emulated compute; scaled by `--time-scale`. |
| `cond {if, then, else}` | Statement conditional over indices, parameters, bindings, and the actor id. |
| `choose {arms: [{weight, body}]}` | Run one arm, chosen positionally by weight (the original *selection*). |
| `phase {name, body}` | Statistics label; no effect on execution or the fingerprint. `name` may be an expression. |
| `trace {file, sha256}` | A captured trace of a real application, executed literally, for calibration; never CLOSED. `file` is relative to the document, JSON Lines as `aeiou-trace export` writes it and `runner/REFERENCE.md` §13 defines it (`DESIGN_REVIEW.md` §3.58; the node was `replay` until 2026-10-02). |
| `timeline {name, caches, resources, workers, body}` | Lanes planned together (contract 0.15, `DESIGN_REVIEW.md` §3.99, brief item 72; V30): the body's main line and every sub-actor of a `parallel` in it is a **lane** with a planned clock, which a `compute` moves by `ns`. The lane planned soonest takes the next step, a tie going to the smaller **lane key** (the main line's is empty; a sub-actor's is its parent's, then the parent's fork ordinal, then its index); a lane runs until its next `compute`; a joined `parallel` holds its parent until its last sub-actor ends and the parent goes on at that end. The plan is a function of the abstract, its parameters, and the seeds, never of the run; draws keep their positional keys. Never a timeline, `channel`, `put`, `take`, `loader`, `barrier`, or `trace` inside one. `aeiou check` and `aeiou dry-run` walk it; `aeiou run` refuses it until its run side is built (item 72 (7)). Its `caches` (contract 0.16, brief item 75; V33), each `{name, tiers}`, a tier ~~`{name, evict, capacity, unit}`: `evict: none` keeps every entry and takes no `capacity`; `evict: lru` evicts the entry used longest ago while a store would pass `capacity`, counted in `entries` (the default) or `bytes`, and an entry larger than the whole tier is not stored~~ `{name, order, capacity, unit, full}` (contract 0.18): at most `capacity` (counted in `entries`, the default, or `bytes`) of entries; while a store would pass it, the entry no lane holds whose `order` values are least, compared in turn, is evicted first, a tie to the entry stored first (`order` is a list of integer expressions over `cached` and parameters, computed when the entry is stored, looked up, or released and kept: `[{cached: touched}]` is LRU, `[{cached: stored}]` FIFO, `[{cached: freed}, {neg: {cached: pos}}]` vLLM's free queue); with no `order`, nothing is evicted. An entry larger than the whole tier is not stored. `full`, what a store that finds no room and no victim does: `skip` it (the default), `wait` (the lane waits in planned time until a release makes room for the whole lookup, first come first), or `fail` (the walk is refused). Since contract 0.19 (V33, V35), a tier may also declare `evict {every, when, count}`: at every planned instant k × `every` ns from the timeline's start (k ≥ 1), while lanes remain and before any lane's step at that instant, if `when` holds, the `count` entries least in `order` that no lane holds are evicted (`when` and `count` read parameters, literals, and `tier used|entries`; `every` parameters and literals); such a tier never evicts at store, so a store past its `capacity` is what `full` says, `skip` a planned drop; it needs a `capacity` and an `order` and is never `full: wait`. And `on_evict {lanes, body}`: each victim, at a tick or a store, runs `body` with `victim` its key, victim i of the eviction on eviction lane i mod `lanes`, at the eviction's planned instant and before any other lane's step there; the body sees the bindings around the timeline (`runner/REFERENCE.md` §2). Its `resources` (contract 0.18, V34), each `{name, capacity}`, counted resources held by `acquire`: a queue with `capacity` servers. A cache and a resource start empty with their timeline and are walked with its lanes, in planned order; a lane that waits is parked, and resumes at the planned time of the release that lets it on. Its `workers` (contract 0.20, V36), each `{name, lanes, staging}` (positive, parameters and literals only): the worker lanes its lanes' `submit`s put bodies on, and `staging`, the bytes a run's unfinished submitted bodies may hold before a store would have been dropped, a gate failure (the run side, brief item 72 (7)). |
| `publish {timeline, group, values}` | An **entry** of the enclosing timeline: `values` (name to expression) at this lane's planned time, which the lanes read with `published` and `entry` (V30); in group `group`, an integer, 0 when absent (contract 0.17): a timeline's entries are counted and indexed within their group, so one timeline every session of an engine shares keeps each session's pool its own. |
| `lookup {cache, tier, seq, per, bind, size, hold}` | The longest run of `seq`'s leading whole chunks of `per` blocks held in tier `tier` of cache `cache` of the enclosing timeline, bound to `bind` as an integer; then ~~every whole chunk, in order, touched if held (a use, for `lru`) and stored if not~~ the chunks the tier holds touched, in order, and then the others stored, in order (contract 0.18; ~~interleaved in contract 0.16~~), as LMCache 0.5.5 looks a prompt up and stores what it missed (V33). A chunk's key is `chunk_key` (`runner/REFERENCE.md` §2). `size`, the bytes of one chunk, exactly when the tier counts bytes. With `hold` (contract 0.18, V34), the chunks found and stored are this lane's under that name until its `release`, never victims meanwhile. `bind` is not positional: `@` and `prev` may not reach it. |
| `acquire {resource, n, hold}` | `n` units of resource `resource` of the enclosing timeline, this lane's under `hold` until its `release` (contract 0.18, V34); the lane waits in planned time while they are not free or an earlier lane waits for the resource, first come first. |
| `release {hold}` | What this lane holds under `hold`, given back (contract 0.18, V34): a resource's units, or a tier's entries, which become victims again, `freed` the release. A lane ends holding nothing. |
| `probe {cache, tier, seq, per, from, bind}` | The longest run of `seq`'s whole chunks of `per` blocks from chunk `from` held in a tier of a cache of the enclosing timeline, bound to `bind` as an integer; nothing changed (contract 0.19, V33). `bind` is not positional. |
| `touch {cache, tier, seq, per, from, count \| chunks}` | The chunks `from` to `from + count`, cut at the sequence's end, or those whose indices the array `chunks` holds, in its order, that the tier holds, touched as one event: the same `touched` for all, `pos` each one's index (contract 0.19, V33). |
| `store {cache, tier, seq, per, from, count \| chunks, size, present, bind, taken}` | The chunks `from` to `from + count`, cut at the sequence's end, or those whose indices the array `chunks` holds (an `array`, another store's `taken`, or a parameter array of integers; an index outside the sequence refused when walked), that the tier lacks, stored as one event, `size` each exactly when the tier counts bytes; those it holds left as they are (`present: keep`, the default) or stored again as if absent (`present: renew`: a new entry, taken; one a lane holds is left as it is). With `bind`, the leading run of the range held after it, short by a planned drop; with `taken`, an array of the indices of the chunks it stored, in the order acted on, read with `len` and `elem` after it (contract 0.19, V33). Never on a `full: wait` tier, which only a `lookup` decides. `bind` is not positional. LMCache's G2 above G3: `store` G2 with `taken: t2`, then `store` G3 with `chunks: t2, present: renew`. |
| `submit {workers, body}` | `body` run on a worker lane of the enclosing timeline's `workers` at this lane's planned instant (contract 0.20, V36): a new lane whose key is (the workers' index in declaration order, the submission's ordinal among those workers'), so at one instant the worker lanes go in the order submitted and after every other lane there; its worker lane is the ordinal mod `lanes`, never the first free one. The body starts from this lane's bindings, frames, and open files as they stand, so its ops carry the indices they would inline and the op set and fingerprint are the body's written inline; in a run its ops wait on its worker lane, never on this lane. It only issues ops (V36). |
| `span {name, body}` | A measured part of a timeline's lane (contract 0.20, V36): the run reports its **D**, from its launch (its planned time plus the lane's lag on entry) to its last op's completion, by `name`, a request's own storage wait, judged through the case's `result.` constraints. No effect on the plan, the op set, or the fingerprint; its body is a body like a `phase`'s. |
| `array {name, count, index, value}` | `count` values computed once, where the node stands, each with `index` bound as a loop index so its draws are positional; read with `elem` and `len` as a parameter array is (contract 0.15, V32). |
| `open {file, flags, mode, expect}` | Flags from the enum in the schema. `DIRECTORY` for `readdir` handles. |
| `close`, `fstat`, `stat`, `fsync`, `fdatasync`, `unlink` `{file, expect}` | |
| `read {file, len, offset, repeat, expect}` | With `offset`: positioned (`pread`), file position unchanged. Without: sequential from the current position. `repeat: until_eof` issues reads of `len` until the known size is exhausted, including the terminating short or zero-length read; each returned count is checked against the computed size. |
| `write {file, len, offset, repeat, expect}` | As `read`, without `until_eof`. |
| `lseek {file, offset, whence}` | `SET`, `CUR`, `END`. |
| `ioctl {file, request, expect}` | `TCGETS` (Python's isatty check), `FIONREAD`, `BLKGETSIZE64`. |
| `fadvise {file, advice, offset, len, expect}` | `posix_fadvise` on an open file: `NORMAL RANDOM SEQUENTIAL WILLNEED DONTNEED NOREUSE`; `len` 0 or absent means to EOF. `WILLNEED` starts readahead on NFS, and pyarrow issues one before every coalesced read (0.2). |
| `truncate {file, len, expect}` | `truncate(2)` of the path, open or not (contract 0.14, `DESIGN_REVIEW.md` §3.92): a changing op, as `ftruncate`. |
| `ftruncate {file, len, expect}`, `fallocate {file, offset, len, mode, expect}` | `fallocate`'s `mode` (contract 0.14) is its flags by name, `KEEP_SIZE`, `PUNCH_HOLE`, `COLLAPSE_RANGE`, `ZERO_RANGE`, `INSERT_RANGE`, `UNSHARE_RANGE`, `WRITE_ZEROES`; absent or empty, mode 0 (allocate and extend), the only mode before 0.14; a mode the kernel takes (V29); part of the op and of the fingerprint. |
| `mkdir {dir, mode, expect}`, `rmdir {dir, expect}`, `rename {from, to, expect}` | |
| `readdir {dir, repeat: until_end, expect}` | `getdents64` until exhausted. |

**Expressions** (scalar, positional, integer arithmetic with floor `div`):
literals (`null` is `none`); `param`, `index`, `ref`, `at {ref, index}`, `actor: id|count`,
`draw dist`; `elem {array, index}`, `len`, `sum` over parameter arrays; `size`, `offset`,
`unit_index`, `units`, `chunks` of a handle (`size` and `offset` of a unit or column handle are
that extent's length and start, framing included), `count` and `dirs` of a dataset; `add sub mul div mod ceil_div min max
neg`; `eq ne lt le gt ge and or not`; `cond {if, then, else}` whose arms may be expressions,
distributions, or handles (this is how a distribution or a phase name is selected by index).
Since contract 0.15: `elem` and `len` also of an `array` in scope; `published timeline`, the
entries the timeline holds before the step being walked, and `entry {timeline, index, key}`,
value `key` of entry `index` in planned order (`index` below `published`, a run-time error
otherwise), V30; since contract 0.17 `published {timeline, group}` and `entry {timeline, group,
index, key}` count and index within one group (0 when absent); `prev {ref, init}`, the value the `let` `ref`, bound directly in a loop's
body, took in the previous iteration of that loop under the same outer indices, `init` in the
loop's first iteration, V31: the same as `ref @ (i − step)` for a positional binding, read
rather than recomputed, so it can carry a value that depends on the timeline. `published`,
`entry`, and `prev` are not positional (what they give is what the step being walked sees), so
`@`, which recomputes a definition at another index, may not reach them.
Since contract 0.16 (brief item 75, V33), a **`seq`**: a sequence of blocks, each `(origin,
offset)`, kept as a shared tree so a prompt built from an earlier one costs one node.
`fresh n`, `n` new blocks whose origin is the node's position, keyed as a draw is (new at
every position, the same when `@` recomputes them); `shared {id, n}`, the first `n` blocks of
the shared prefix `id`, the same in every lane, actor, and run (a system prompt); `prefix [s,
k]`, the first `k` blocks (`0 <= k <= seq_len`, a run-time error otherwise); `cat [a, b]`;
`seq_len s`; `chunk_key {seq, chunk, per}`, the key of whole chunk `chunk` of `per` blocks, a
non-negative integer, the chained hash of every block to its end, so two sequences give one
key exactly when they hold the same blocks up to it, however they were put together. A `seq`
may be bound, published, read back with `entry`, and carried with `prev`; it is not a number,
a condition, or a name's field (V27).
Since contract 0.18: `now {}`, this lane's planned time in nanoseconds, only in a timeline
(V30) and not positional, as `published` is; `cached attr`, only in a tier's `order` (V33), an
attribute of the entry being ordered: `stored`, `touched`, and `freed`, the tier's event counts
when it was stored, last looked up, and last released (`stored` until then); `hits`, the lookups
that found it; `pos`, its index in the sequence of the lookup that last found or stored it;
`size`, in the tier's unit.
Since contract 0.19: `tier attr`, only in a tier's `evict` `when` and `count` (V33): `used`, its
entries' size in its unit, and `entries`, their number; `victim {}`, only in an `on_evict` body
(V35), the key of the entry it runs for, as `chunk_key` gives it.

**Handles:** `ref` (a binding); `file {dataset, id}` (a dataset file by id; an `array` dataset's single file is `id: 0`) or
`file {of, chunk}` (the container file, or chunk object `k`, of a sample handle); `dir {dataset,
id}`; `inventory dataset` (the dataset's inventory, contract 0.9); `object {namespace, fields}`; `consume dataset` (next sample without replacement);
`pick {dataset, dist}` (a sample with replacement, uniform or by a distribution over ids);
`unit {of, index}` (unit `index` of the file `of` holds or is; without `index`, the unit
holding the sample `of`); `column {of, index}` (column chunk `index` of a unit). A sample
handle used where a file is expected means its container file. Under `stream` access,
`consume` and `pick` return **file** handles (the shuffle runs over shards, `GRAMMAR_OPTIONS.md`
§6.2) and the positions, epochs, and `drop_last` are counted in files.

**Distributions:** `const`, `uniform {lo, hi}` (integer, `[lo, hi)`), `uniform64`, `normal
{mean, sd, min, max}`, `lognormal {median, sigma, min, max}`, `empirical {values, weights}`,
`zipf {s}`, `hotset {fraction, weight}`, `mixture [{weight, dist|null}]`. Wherever the schema
says `distref`, a `param` or a `cond` that evaluates to a distribution is also accepted.

**Datasets** (one shape since 0.8; `files {…}` and `regions {…}` before, `DESIGN_REVIEW.md`
§3.72): `{pattern, layout, access, count, size, seed, samples_per_file, chunk, slot, format,
inventory, protocol, doc}` (`protocol`: V17). The hierarchy: a dataset's units of storage are files or
objects (`protocol`); `layout` says how a unit holds the dataset's items: `whole` (one item),
`chunked` (part of one: `chunk` bytes a unit, named by `{k}`), `compound` (several variably
sized items: `samples_per_file` a file, framed by `format`), or `array` (`count` fixed-size
slots of `slot` bytes in one file, its pattern without fields); the format's `framing` says how
a compound file's bytes surround its items. `access` says how the application finds them:
`map` (samples drawn from the positional shuffle, read by offset; PyTorch's map-style),
`stream` (files drawn from it, read in order; iterable-style), or `indexed` (looked up by id
with `file` or `pick`, never consumed). The fields each layout takes are V20; access, V21.
`count` is items: samples, or an array's slots. Sizes are drawn from the dataset
seed, never from `--seed`. Patterns use `{field[:format]}` with fields `id` (and `k` for chunk
objects) and the forms `{id:09}`, `{id div 1300:05}`, `{id mod 16}`, `{conv:016x}`; the
divisor of `div` or `mod` is a positive number or (contract 0.10) the name of an integer
parameter, `{id div files_per_directory:05}` (V23), bound to its value before any name is made,
so the resolved definition, and the dataset id, carry the number (`DESIGN_REVIEW.md` §3.75); a
dataset's directories are the distinct prefixes up to the last `/`, enumerated in id order.

**Terms** (contract 0.10, `DESIGN_REVIEW.md` §3.71 point 6, §3.75). A **sample** is an item a
job draws; a **file** is a file or object of the dataset; a **directory** is a distinct prefix of
its names. Training abstracts name their layout parameters `samples` (the dataset's `count`),
`samples_per_file` (a `compound` dataset's), and `files_per_directory` (the divisor of `{id div
files_per_directory}`), so whoever sizes a corpus sets the same names in every abstract;
`files` and `directories` follow from them and are never parameters.

**Inventory** (contract 0.9, `DESIGN_REVIEW.md` §3.73): `inventory {name, entry}` on a consumed
dataset is a file list of it, the file `name` directly in the dataset's root, `count × entry`
bytes (`entry` an expression: bytes per item listed). `aeiou datagen` writes it as payload
(its own key, so no id's bytes are its) once the corpus is written; the `inventory` handle
names it, and a job reads it in place of a walk of a large corpus (§3.70 item 6). It is part of
the resolved definition, so of the dataset id. Under `aeiou run --subset` its reads are issued
no further than its size at the run's count (`runner/REFERENCE.md` §5, *Subset runs*). Rule V22.

**Container framing** (`format {class, reader, version, framing}`, 0.2; `layout` until 0.8). Without a format class
the framing is *packed*: a file is its samples back to back, `offset(s)` the prefix sum. A
format class declares `framing`, and every offset the runner computes follows from it, so the
runner stays format-ignorant: a file is `file_header ‖ units ‖ file_footer`, aligned to
`file_align`; a unit (row group, record batch, chunk; `unit` samples each, default
`samples_per_file`) is `unit_header ‖ column chunks ‖ unit_footer`, aligned to `unit_align`; a
column chunk is `header ‖ rows`, aligned to `align`; a row is `row_header ‖ fixed ‖ its share
of the sample ‖ row_footer`, aligned to `row_align`. Headers and footers may grow
`per_sample` and `per_unit`. A column's `weight` is the share of each sample's bytes it
carries (`floor(size × weight)`, the last positive weight taking the remainder; weights sum
to 1); `fixed` is bytes per row that are not sample bytes (an int64 label, an offset entry).
Every field is an expression over parameters, so the framing is part of the resolved dataset
definition the manifest compares; `writer` is opaque class-specific writer settings, likewise
compared. `offset(s)` of a sample is the start of its payload in the one column; a sample
split over several columns has no single offset (address its unit or a column). The
geometry a format class declares is the geometry its writer produces, checked at datagen.

**Namespaces:** `{pattern, fields, size, seed, input, same_run, protocol, doc}` for objects
the run creates (`input`: V14; `same_run`: V15; `protocol`: V17). `size` is an
expression or `as_written` (§4, rule V4).

**Actors:** `{count, body, doc}`; `count` defaults to `--gpus` (the reserved `gpus`, which no
expression reads: `{param: gpus}` is an unknown parameter). Instances have global ids
`0..count`; `{actor: id}` reads it, `{actor: count}` the count.

## 4. Semantic rules the validator adds

The schema cannot express these; `check.py` does, and so does the Rust validator
(`runner/aeiou/src/validate.rs`, `aeiou check`), whose messages CI diffs with `check.py`'s over
every committed AST; most messages name their rule. V5 holds by
construction (the schema has no clock or counter to read), V9 is the builder's, V10 is the
runner's evaluation, and V16 the runner's at `aeiou run`; every other rule, V1 to V34 (~~V1 to V27~~, ~~V1 to V32~~, ~~V1 to V33~~), both
checkers enforce.

- **V1 Names resolve.** Every `param`, dataset, namespace, channel, index, and `ref` is
  declared in scope. `at` may name a binding defined later in the same loop body. A
  parameter's value may name another parameter, never itself through others (2026-10-15):
  every parameter on such a cycle is refused with it (`pa -> pb -> pa`), on the defaults and
  by the runner again on the values given, and the document is judged no further.
- **V2 `gpus` is reserved.** It may not appear in `params`.
- **V3 `at` decreases.** An `at` on a binding of the same loop body (the binding being
  defined, one defined later, or one defined earlier in that body; ~~a self-reference or a
  forward reference~~ the wording until contract 0.5, which the runner never followed: a
  chain through an earlier binding looking ahead would not end, `DESIGN_REVIEW.md` §3.57)
  must use an index of the form `{sub: [{index: i}, e]}` where `i` is the innermost loop
  index and `e` is provably `≥ 1`. A binding of an enclosing body is free. Provably `≥ k`,
  for `k` 1 or 0: a literal `≥ k`; a `ref`, `param`, or `draw` whose distribution has `min ≥
  k` (`uniform` with `lo ≥ k`, `normal` or `lognormal` with `min ≥ k` and either no `max`
  or a `max` known not to be below it, `empirical` with all values `≥ k`, a `mixture` with
  at least one non-null arm and every non-null arm qualifying, `const` of such a term); `add`
  of a term `≥ k` and a term `≥ 0` (contract 0.5); and for `k = 0` also any `mod` (the
  runner's `mod` is Euclidean, so the result is in `[0, |b|)`) and a loop index whose loop
  has no `from` or a `from` provably `≥ 0` (steps are positive; `parallel` and `loader`
  indices start at 0). Nothing else qualifies (`mul`, `min`, `max`, `div`, `when`, a
  parameter with a literal default), so `kp @ (r − (r mod d + 1))` is accepted and `x @ (r −
  2·d)` is not. The runtime guard for a null arm is the author's `cond`. An `at` whose index
  falls below the loop's `from` evaluates the binding's non-recursive arm (the "fresh draw"
  of `ABSTRACTS.md` §9.5). The rule is judged on the document's parameter defaults; the
  runner judges it again on the parameter values in effect, before a run or a dry run, since
  a value may replace a distribution with one whose minimum is lower. A required parameter
  (no default) has no value on the document, so a `param` or `draw` of one qualifies there,
  and its value is judged when one is given: by `aeiou-params check` and `lock` on each
  fragment, and by the runner on the values in effect (contract 0.13). The runner clamps a
  `normal` or `lognormal` to `min` and then to `max`, so `min` bounds it only under a `max`
  that is known (a literal, or a parameter whose value is a number) and not below it, and a
  `min` above a known `max` is an error in its own right (2026-10-14). Under a proof that
  is wrong anyway, the runner refuses an `at` that would evaluate a loop body at an index not
  below one it is already evaluating, rather than recursing without end. **Which binding**
  (2026-10-14, contract 0.10, no committed AST affected): `x` is a `let` of the body the
  `at` is written in, before or after it, when that body has one, else the binding of `x`
  in scope from an enclosing body; a body's `x` shadows an outer `x`, as both checkers have
  always assumed (the runner took the outer one until then). The definition re-evaluated
  resolves its own names where it is written: a `ref` reads the nearest earlier `let` of its
  body, at the shifted index, else a binding of an enclosing body, never one of a body
  nested inside it. An `at` naming a binding its body defines more than once is refused:
  which of the two it reads is not defined.
- **V4 Sizes are computed, never observed.** For a namespace with `size: as_written`, an
  object's size is ~~the sum of the write lengths in the sequence that created it~~ the size
  POSIX gives the file the sequence that created it makes (revised 2026-11-03,
  `FS_API_SWEEP.md` S-19): the end of its furthest write, set by a `truncate` or `ftruncate`,
  extended by a `fallocate` without `KEEP_SIZE`, shrunk by a `COLLAPSE_RANGE` and grown by an
  `INSERT_RANGE` of its length. `until_eof`
  on such an object is allowed only through the handle binding those writes used, which pins
  it to the creator's position. Elsewhere a reader states its length. `fstat` results are
  never consumed by the abstract.
- **V5 Finite and timing-free by construction.** Every loop bound, width, repeat, and
  condition is an expression, and expressions have no inputs except the seed, the actor id,
  the site, indices, parameters, and dataset metadata. There is no clock, no completion order,
  and no counter to read. The op multiset is therefore fixed before the run.
- **V6 `consume` needs a position.** It must sit inside at least one loop (normally the
  loader's batch loop and an item loop); its position is `actor + count × (b × B + j)` over
  the enclosing loader/loop indices, epochs are `drop_last`. A dataset is consumed in one
  place (added 2026-10-14, contract 0.10, no committed AST affected): a `consume` has no site,
  so its position is a function of the actor's number and its enclosing frames' ordinals
  alone, and a second `consume` of the dataset (in the same body, in a sibling loop such as
  an eval phase after a train phase, or in another actor) reaches the same positions and
  returns the same samples, a reuse the job does not have. The second is refused; consume once
  and use the handle (a `let`) in each place, or put the one `consume` in an inner loop.
  Every loop, `parallel`, and `loader` around a `consume` has a count fixed for the actor
  (added 2026-10-15, contract 0.10, no committed AST affected): the ordinal is row-major at
  fixed counts, so a count (a loop's `from`, `to`, or `step`, a `parallel`'s `width`, a
  `loader`'s `batches`) that names an enclosing index, an `at`, a binding that does, or a draw
  inside a loop repeats positions (`loop i < 3 { loop j < 3 − i { consume } }` reaches
  position 2 at (0, 2), (1, 0), and (2, 0)). It is refused, naming the loop; give the loop the
  most it can be and skip the rest with a `cond`. Parameters, the actor number, and draws at
  the actor's top are fixed for the actor.
- **V7 Object fields match** the namespace's declared fields exactly.
- **V8 `empirical`** has as many weights as values.
- **V9 Access mode.** `map` over a container the format class cannot address randomly is
  refused by the builder; the runner checks the dataset against the manifest at startup.
- **V10 Continuous draws round** to the nearest integer wherever an integer is consumed
  (sizes, counts, indices, nanoseconds).
- **V16 a `trace` that creates paths runs in one instance** (added 2026-10-02, with the
  node, `DESIGN_REVIEW.md` §3.58). A `trace` whose file creates paths (the header's
  `creates`) may not run in an actor template of more than one instance, whose copies would
  write the same files. The count is an expression, so `aeiou run` checks it with the
  resolved counts before the gate (`runner/aeiou/src/trace.rs`); neither validator does.
- **V12 Datasets are read-only** (added 2026-09-30; `mkdir` and `rmdir` 2026-10-14, as the
  builder and V14 already refused them; `truncate` 2026-11-02, contract 0.14). No `write`, `truncate`, `ftruncate`, `fallocate`, `unlink`,
  `rename`, `mkdir`, or `rmdir` may target a dataset file, directory, sample, region, or chunk
  (through a binding or directly), and `open` on one may not carry `WRONLY`, `RDWR`, `CREAT`,
  `TRUNC`, or `APPEND`. A binding may name what its value may be where it is bound: an alias's
  or an `at`'s binding, either arm of a `cond` (2026-10-15: a handle chosen by `cond` from a
  dataset handle was written through unrefused). Writes go to namespaces. This is what makes the manifest (§7) true for the run.
- **V13 Reserved names** (added 2026-09-30). No path component of a dataset or namespace
  pattern may begin with `.aeiou`; that prefix belongs to the manifest and any future
  sidecar. Two datasets may not share a root (the constant directory prefix of the
  pattern; an `array`'s, the directory of its file). Nor may one
  dataset root lie inside another (added 2026-10-01: `aeiou datagen` wants each root empty and
  to itself; a dataset at the top level, root ``, therefore excludes any other dataset).
- **V11 Scope.** A `let` is visible to later siblings and to child bodies, not to sibling
  bodies (bind a handle above two phases that share it).

- **V14 Input namespaces are read-only** (added 2026-09-30). A namespace declared
  `input: true` holds objects a previous run wrote; the run that declares it reads them and
  may not `write`, `truncate`, `ftruncate`, `fallocate`, `unlink`, `rename`, `mkdir`, or `rmdir` an
  object of it, nor `open` one with a write-mode flag, through a binding that may name one as
  V12 reads it. Namespaces that share a root share its
  manifest (§6), so they must agree on `input`. The runner requires the writer's
  `.aeiou-namespace.json` at the root and never empties an input root. Reasoning in
  `DESIGN_REVIEW.md` §3.24.
- **V15 `same_run` needs `input`** (added 2026-10-02, contract 0.4). A namespace declared
  `same_run: true` is read under names that are positional draws of the run that wrote it
  (a conversation id drawn at a new conversation, say), so only a run with the writer's
  draws can name its objects. The validator requires `input` beside it. The runner compares
  this run with the manifest before the gate and refuses when `--seed` or `--gpus` differ
  from the writer's, or when a parameter that both abstracts declare has another resolved
  value; the message lists each difference. A parameter only one of them declares is not
  compared. A namespace without `same_run` is not compared this way: a checkpoint restore
  may run with any seed. What the rule cannot see is whether the two abstracts place their
  draws at the same sites; that is the authoring script's job and a run test's
  (`DESIGN_REVIEW.md` §3.52, §3.54).

- **V17 namespaces sharing a root declare one protocol** (added 2026-10-09, contract 0.6). A
  dataset or namespace may declare `protocol: s3` (`object` until 0.7; absent: `posix`): where it lives, which
  a run places with `--endpoint` (`runner/REFERENCE.md` §4). Namespaces sharing a root share
  its place as they share its manifest (V14), so they agree on the protocol. Datasets need
  no such rule, since their roots are distinct (V13). The protocol is not part of a dataset
  id or a namespace's resolved definition: where a corpus lives is not what it is. ~~The
  runner refuses `object` until its object engine is built~~ The runner reads an `s3`
  dataset through its object engine (`runner/REFERENCE.md` §16, 2026-10-09) ~~and refuses an
  `object` namespace until the engine writes~~ and, since the engine writes (the same night),
  reads and writes an `s3` namespace too, under V18 (`DESIGN_REVIEW.md` §3.65).
- **V18 an object is written once, in order** (added 2026-10-09, contract 0.6, before any
  committed AST declared an object namespace). An object of a namespace declared `protocol:
  s3` is made by one upload: the writes of one handle, each at the end of the last, sent
  at its `close` (`runner/REFERENCE.md` §16). So the forms that rewrite, extend, or read an
  object in place have no object form and are refused: `open` with `APPEND`, `RDWR`, or
  `EXCL` (a conditional create the engine does not send), `truncate` (contract 0.14), `ftruncate`, and `fallocate`. The
  validator sees the ops, not the offsets, which are positional expressions: a write the
  upload has not reached fails the run when it comes (`ESPIPE`), as a structural check does.
  Revised 2026-10-15 (RC1 review), no AST changed: an upload is begun by `WRONLY` alone,
  so `CREAT` or `TRUNC` without it is refused (a read-only handle would make or empty an
  object it never writes); and since the `close` sends the upload, an `open` with `WRONLY`
  is followed in the same body by a `close` of the same handle (the same expression), before
  an `open` of it again or a `let` of a name it reads. A close in a nested body (a `cond`
  arm, a loop, a sub-actor) does not count: it may not run, and the rule stays one a reader
  checks by eye. An upload a run still finds unsent when its actor ends fails the run.
- **V19 an API for each protocol with names, of one kind** (added 2026-10-09, contract 0.7).
  `posix` and `cache` are declared only when the abstract has a `posix` name (a dataset or
  namespace declaring it or none, or a `trace` node, whose files are under `--root`), `s3`
  only when it has an `s3` name: an API for a protocol without names would change nothing.
  With both, the declared APIs, defaults counted, are of one kind: `async` with `io_uring`
  or `libaio`, `blocking` with `sync`, `posix-aio`, or `mmap`. A run puts its actors on event
  loops when either API is event-driven, and a mix (a thread blocked on S3 while a loop runs
  its POSIX ops) waits for a traced application that shows it (`DESIGN_REVIEW.md` §3.65).
- **V20 a layout's fields** (added 2026-10-13, contract 0.8). `whole` takes none of
  `samples_per_file`, `chunk`, `slot`, `format`; `chunked` needs `chunk`; `compound` needs
  `samples_per_file` and may have `format`; `array` needs `slot`. A pattern's fields: an
  `array`'s none (it is one file; a sharded array is not built), a `chunked` dataset's `{id}`
  and `{k}`, the others' `{id}` alone (`DESIGN_REVIEW.md` §3.72); a field of another name is
  refused (2026-10-15: one passed both checkers and failed the run, which has no value for it).
- **V21 access** (added 2026-10-13, contract 0.8). An `array` is `indexed`. `consume` takes a
  `map` or `stream` dataset; an `indexed` one is looked up by id (`file`, `pick`). A consumed
  dataset's directory part is `{id div D}` or has no `id` field, never `{id mod M}`, so a
  subset of it is whole directories (`DESIGN_REVIEW.md` §3.72).
- **V22 inventory** (added 2026-10-13, contract 0.9). Only a `map` or `stream` dataset has an
  `inventory`. Its `name` is a file name (no `/`, no field braces, not `.` or `..`), not
  beginning with `.aeiou` (V13), and not a name the pattern can produce in the dataset's root
  (each field read as the characters an integer formats to). The `inventory` handle names a
  dataset that declares one, and V12 holds for it: it is read-only (`DESIGN_REVIEW.md` §3.73).

- **V23 divisor** (added 2026-10-13, contract 0.10). A name after `div` or `mod` in a dataset's
  or namespace's pattern is a declared parameter of kind `int` (its default an integer, or,
  required, `kind: int`; contract 0.11) (`gpus` is not
  declared, so it is never one); a value of zero or less is refused when the model is built
  (`DESIGN_REVIEW.md` §3.75).
- **V24 a sub-actor positions its ops on an inherited handle** (added 2026-10-14, contract
  0.10, no committed AST affected). In a `parallel` or `loader` body, a `read` or `write`
  without an `offset`, and any `lseek`, names a handle that body opened earlier (an `open` of
  the same handle expression, in document order, in the innermost such body). A handle the
  parent opened is a descriptor the sub-actors share, with one kernel file position, so
  where such an op lands would depend on which sub-actor ran first; the runner's model gives
  each sub-actor the parent's position at the fork (`runner/REFERENCE.md` §4, *Threads*).
- **V25 a dataset's size is never below 0** (added 2026-10-14, contract 0.10, no committed
  AST affected). A size is a byte count; one below 0 used to pass and reach `aeiou datagen`
  cast to an unsigned count (16384 PiB for `small − 100` at `small` 10). The validator
  refuses a `size` the document shows can be below 0: a number known below 0 after rounding
  (V10; a literal, a parameter whose value is a number, or `add`, `sub`, `mul`, `min`, `max`,
  `neg` of such), a `const` of one, a parameter whose value is a distribution that qualifies,
  a `uniform` whose `lo` is, an `empirical` with such a value, a `normal` or `lognormal` whose
  least draw is after the runner's clamp to `min` and then to `max` (a `normal` with no `min`
  and an `sd` not 0, a `lognormal` with a `median` below 0, and `uniform64`, are unbounded
  below), or a `mixture` with such an arm of positive weight; a size whose least value is not
  a finite number (an overflow past f64, `inf − inf`) is refused too, and the value printed is
  the runner's rounding, unsaturated (2026-10-15); a `min` or `max` with an operand not a
  number, and a `mixture` with an arm of positive weight whose least value is not finite, are
  no finite number either, whatever the order of operands and arms (2026-10-15). An
  `array`'s sizes are clamped to `[0, slot]` and are exempt. Judged on the parameter defaults, and by the runner again on
  the values in effect (as V3); what the document does not show (a bound through `div`, say)
  the runner refuses when it draws it, naming the dataset and the sample.
- **V26 a channel is declared by the actor** (added 2026-10-15, contract 0.10, no committed
  AST affected). No `channel` or `loader` inside a `parallel` or `loader` body, at any depth.
  A channel is the actor's, shared by every sub-actor, and one declared in a loop is declared
  again in each iteration, replacing the last once nothing put on it is left untaken
  (`runner/REFERENCE.md` §4); declared by sub-actors it was declared once by each, over the
  others' when theirs happened to be empty, so the run failed, hung, or passed as timing had
  it. Declare it before the fork; the sub-actors put and take on it.
  A loader's workers run beside the actor, so a channel they `put` or `take` on (in the
  loader's body, at any depth) is declared at one site, and that site is outside every loop or
  in the body the loader is in, the loader then declared at one site too (2026-10-15): the
  actor declaring it again while the workers ran (in a loop the loader was declared outside
  of, or at a second site), a worker reached the old channel or the new one as timing had it.
  A `take` in a loader's body, at any depth, is refused (2026-10-15): the workers took beside
  each other and the actor, so which of them got the item the actor put, and whether the run
  finished, was timing (it had passed both checkers); a loader's body only puts.
- **V27 a value is of a kind the runner reads where it stands** (added 2026-10-15, contract
  0.10, no committed AST affected). The schema lets any scalar stand where an expression
  does, so `"count": "gpus"` passed both checkers and failed `run` with "expected an
  integer, got str". The validator refuses a value whose kind the document shows (a literal;
  a `param` by its value in effect, judged on the defaults and by the runner again on the
  values given, as V3; an `elem` of a parameter array whose elements are of one kind; a
  `ref` or `at` by the value its binding was given; a handle or a distribution; an
  expression whose result is an integer (`index`, `actor`, `count`, `size`, …) or a bool (a
  comparison, `and`, `or`, `not`) whatever its operands; a `cond` whose arms are of one kind)
  where the runner refuses that kind: a string, `null`, a distribution, an array, or a
  handle where it reads an integer (an actor's `count`, a dataset's `count`, geometry, and
  framing, a namespace's `size`, `from`, `to`, `step`, `width`, `workers`, `prefetch`,
  `batches`, `capacity`, `seq`, `ns`, an op's `len`, `offset`, and `repeat`, a handle's
  `id`, `chunk`, and `index`, `at` and `elem` indices, `uniform` bounds) or a number (the

## 5. Positional semantics, stated once

- A draw at site `s` inside loops with indices `(i₁ … iₙ)` on actor `a` is
  `hash(seed, a, s, i₁ … iₙ)`. The same site at the same position yields the same value, so a
  `let` is the way to use one draw twice, and `at` is the way to use a draw made at another
  index.
- Dataset sizes and layouts are functions of `(dataset seed, id)`; namespace content is a
  function of `(namespace seed, hash(path), offset)`.
- The fingerprint is the sum over ops of `hash(op kind, path, offset, len, flags)`, summed by
  the coordinator across actors; `phase`, `expect`, and results are excluded; issue order is
  never hashed. Its exact definition belongs to the runner and is not fixed by this schema.
  **The runner's definitions (2026-09-30)**, for the hash functions, the word sequence, the
  permutation, the `consume` position, `x @ i`, `until_eof`, and the fingerprint, are in
  `runner/REFERENCE.md` §2; the golden tests there pin them.

## 6. Dataset manifest (decided 2026-09-30)

`aeiou datagen` writes one manifest per dataset root, named **`.aeiou-dataset.json`**, and
`aeiou run` refuses to start unless every dataset the abstract declares matches its manifest.
Reasoning in `DESIGN_REVIEW.md` §3.21.

- **Root.** The constant directory prefix of the pattern (`train/` for
  `train/{id div 1300:05}/img_{id:09}.jpg`); for an `array`, the directory holding its file. The manifest lives directly in that directory.
- **Name.** The leading `.` and the `.aeiou` prefix keep it out of the data: rule V13 means no
  pattern can generate a colliding or look-alike name, naive globs and ImageFolder-style walkers
  skip dotfiles, and the runner's structural check on `readdir` ignores `.aeiou*` entries (the
  real `getdents64` still returns them, as it would any dotfile). The verifier and datagen
  treat `.aeiou*` as metadata, never as data to generate or check.
- **Normative content**, compared by `aeiou run` for exact equality with what it resolves from
  its own abstract and the parameters in effect: `dataset` (the dataset's entry
  with every `param` reference substituted by the value used, in canonical form: sorted keys,
  provenance removed), `payload` (generator name and version, dedupe ratio, compression ratio,
  block size, the positional wrapper's version), `format` (format class, writer library and
  version, framing fields) when the dataset has a format class, and `manifest_version` (3 since
  2026-10-13, contract 0.8's dataset shape).
- **Provenance**, recorded and printed but never compared: the abstract's `name` and
  `ast_sha256`, the full parameter values at datagen time, the datagen version, host, start
  and end time, and the count of files actually written; since 2026-10-04 also
  `ranks`, `hosts` (each rank's host, files, bytes, start and end), and `direct` (written with
  `O_DIRECT` everywhere); since 2026-10-12 `dataset` (the dataset's name in the abstract, which
  `aeiou datagen --resume` uses) and, after a resume, `resumes` (each resume's ranks, hosts,
  counts, times, and `direct`), `files_written` and `bytes_written` then counting every
  datagen's files once; after `aeiou datagen --grow` or `--shrink`, `resizes` (each change's
  `op`, the count and dataset id it started `from`, the count it went `to`, ranks, hosts,
  counts, and times), `files_written` and `bytes_written` then the corpus's own; after
  `aeiou datagen --settle`, `settles` (each settle's `state` settled, the count `asked` and
  the `count` kept, ranks, hosts, counts, times), and the `resizes` entry it ended marked
  `settled` with the count kept.
- **Identity.** The SHA-256 of the canonical form of the normative content is the dataset id.
  `aeiou run` prints it with every result, next to the AST hash and the parameters in effect;
  a result is those three things.
- **Atomicity.** ~~Written last, to a temporary name and renamed, so a datagen that did not
  finish leaves no manifest and a run refuses.~~ Since 2026-10-12 (`DESIGN_REVIEW.md` §3.70,
  `manifest_version` 2) written first and rewritten as the corpus is written, each time to a
  temporary name and renamed (since 2026-10-15, RC1 review R68, the temporary file flushed
  before the rename and the directory after, as a namespace manifest's): `state` is
  `writing` before the first file, with `progress`
  (the id ranges not yet written and flushed, the counts, the time), rewritten once a
  progress window, and `complete` with no `progress` once every file is; neither is part of
  the normative content. A grow or shrink (`aeiou datagen --grow N ROOT`, `--shrink N ROOT`)
  writes the new count's manifest first, `growing` or `shrinking`, its `progress` also holding
  `from`, the count the corpus had, so a resume knows what to remove. Since 2026-10-12
  (`DESIGN_REVIEW.md` §3.70) `progress` also holds `progress_secs` (the window) beside
  `updated` (now seconds to the millisecond), so `--resume` and `--settle` refuse a manifest a
  datagen may still be writing; `stopped` (the time a datagen that stopped, by Ctrl-C or a
  failure, last wrote it, which lifts that refusal); `claimed`, the boundary of the runs handed
  out in id order (from the top down in a shrink), and `claimed_to`, the mark no run handed
  out reaches past; and, from `aeiou datagen --settle ROOT`, `settle` (`asked`, `count`), the
  count the corpus is settling at in place of the one asked. A run refuses any state but `complete`. On several hosts rank 0
  writes it, merging every rank's progress note, and says `complete` once every rank has
  reported its part, so `complete` means the whole corpus. The Python writer writes it once,
  last, `complete`.
- **Exact match, no relaxation.** A larger dataset is not accepted for a smaller declared
  count: `dirs` and `readdir` would see extra entries, and `zipf`/`hotset` rank orders are
  permutations over the declared count. Any mismatch is a refusal with a field-by-field diff.
  (~~Planned~~ built 2026-10-13, `DESIGN_REVIEW.md` §3.62, §3.70 item 6: `aeiou run
  --subset` runs over the first *S* ids of a larger corpus, so one long datagen serves a
  series of runs that grow toward the SUT's saturation point; names, sizes, and payload
  groups are functions of the id alone, so only this comparison changes, against the
  definition at the corpus's count, `runner/REFERENCE.md` §5 *Subset runs*.)
- **Namespaces are the mirror image.** They have no manifest, but stale contents change the
  workload (`stat` with `expect: [ENOENT]`, `CREAT|TRUNC` semantics, the KV-cache hit model),
  so `aeiou run` refuses a non-empty namespace directory unless `--clean-namespaces` is given,
  and a namespace root may not lie inside a dataset root.
- **Not a security boundary.** The manifest sits on the system under test; under the
  interposition test a shim could serve a fake one. That is the fraud domain: rules, the
  published dataset id, and the offline verifier, which takes the manifest as its input.

**Namespace manifest (added 2026-09-30).** A run that creates objects leaves
`.aeiou-namespace.json` at every namespace root it wrote (one per root, so namespaces sharing
a root share it), written last and atomically. It carries the resolved definition of each
namespace at the root (`pattern`, `fields`, `seed` with parameters substituted; `size` is
each abstract's own model, `as_written` for a writer and an expression for a reader, and is
not compared), the abstract's name and hash, seed, `gpus`, the parameters, each rank's host
and GPU id range, start and finish times, the count of objects created, and the list of
objects with the GPU id that created each (omitted above 100 000 objects). A run that
declares a namespace `input` (V14) requires the manifest at its root, refuses on a differing
definition (and, for a `same_run` namespace, on a seed, an instance count, or a common
parameter that differs from the writer's, V15), reports the write-to-read gap (`--max-gap` makes a long one an error), and counts
the input objects it opens on the host that wrote them (`--require-cold` makes any such read
an error; `--rank-rotate` is how a read run on the same hosts avoids them). This is the
checkpoint write-then-restore handoff of `PROJECT_BRIEF.md` §8.

## 8. Parameter files (added 2026-09-30)

The shape/parameters split of `GRAMMAR_OPTIONS.md` Option D ("three sources fill the AST's
slots"). The AST is the *shape*: named slots whose defaults are placeholders or one reference
set. A **parameter file** fills the slots with values from configuration, measurement, and a
trace, so one published shape can carry several parameter sets, and a fitted set is reviewed,
hashed, and published on its own. `params.schema.json` is the form; `../workloads/` holds
the committed sets; the reasoning is `DESIGN_REVIEW.md` §3.27.

- **Form.** `{"params_version": 2, "abstract": name, "ast_sha256"?: hex, "doc"?: text,
  "params": {name: entry, …}, "run"?: {option: entry, …}, "provenance"?: {…}}`, each entry
  a value with its **state** (contract 0.11, `DESIGN_REVIEW.md` §3.78 point 4):
  `{"default": v}`, a value a later layer may replace; `{"locked": v}`, final; or
  `{"required": true}`, no value, which a later layer must give. A value has the form of a
  parameter default (§2): a scalar, a distribution, or an array of these. Files are named
  `<abstract>.<set>.params.json`. ~~`params_version` 1, a bare value for each name~~
  (until 2026-10-22; every committed set was converted, each value a default).
- **Rules** (the runner's, in `runner/aeiou/src/eval.rs`; `aeiou-params check` mirrors
  them). `abstract` must be the AST's name; `ast_sha256`, when present, must be its hash (a
  set fitted for one exact shape); every name must be declared; `gpus` may not appear; a value
  replaces a default of the **same kind**: a scalar for a scalar, a distribution for a
  distribution, an array for an array (any length, elements of the default's element kind).
  The kind rule exists because the builder fixed at build time how each slot is consumed (a
  distribution is drawn, an array is indexed), so a change of kind would not be a change of
  value. `cli: false` restricts `--param`, not parameter files: the file *is* the published
  set. `--param` now keeps the kind too. Down to the number (2026-10-15): where the default
  is an integer (an array's elements are), an integral float is that integer (`3e3`,
  `3000.0`: the resolved definition and the dataset id are those of `3000`), and a fractional
  one is refused, never rounded.
- **Precedence.** `aeiou run AST --params-file A --params-file B --param k=v`: the defaults, then `A`,
  then `B`, then `--param`, where a later one never replaces what an earlier file locked
  (`--param steps: locked by A`) and a `required` entry leaves the parameter with no value
  until a later one gives it. A `run` table is refused here: the runner's identity options
  come from a lock's runs (below). What a result reports is still the parameters in effect (§6: a
  result is the AST hash, the parameters in effect, and the dataset ids); the file names and
  their SHA-256 are printed in the header line and recorded in the dataset manifest's
  provenance, never compared. The coordinator's configuration hash covers the resolved values,
  so every host must have the same files.
- **Tools.** `aeiou-params defaults AST` writes the defaults as a starting set (`--pin` records
  the AST hash); `aeiou-params check AST FILE…` validates; `aeiou-params safetensors AST
  SHARD… -o FILE` builds `safetensors_load`'s tensor table from real safetensors shards (the four
  parallel arrays of `ABSTRACTS.md` §4b that motivated the split, `DESIGN_REVIEW.md` §3.19;
  the tensor-parallel split of each tensor comes from name patterns, `--column` and `--row`,
  with Llama-shaped defaults); `aeiou-params npz AST ARCHIVE…` reads `npy_per_sample`'s
  archive framing (`framing`, `cd_len`) from real `.npz` files and compares it with the
  defaults. `aeiou-fit` (trace fitting, `ABSTRACTS.md` §11, not yet built) will write the
  same form.

### Use cases, rules, and the lock (contract 0.11, 2026-10-22)

The reasoning is `DESIGN_REVIEW.md` §3.78. Four layers that only narrow: the abstract (its
declarations), the **use case** (a case directory whose `case.toml` lists each run's
abstract and its fragments, parameter files of `params_version` 2), a benchmark's **rules**
(`rules.schema.json`: `freeze` by state, `constraints` over the runner's `fact.` and
`result.` names; it names no parameter), and the submission (the required values and the
system under test's settings, on the command line, never shipped). Fragments of one layer
combine by agreement, two that set a name differently refused, never last-one-wins.
`aeiou-params lock CASE [--rules FILE]` writes the **lock** (`lock.schema.json`,
`lock_version` 1): for each run its abstract's path below `workloads/` and `ast_sha256`,
every parameter's entry and source, the `run` table; the freeze and the constraints (each
with its text, its expression form with `{"fact": n}` and `{"result": n}` leaves, and the
names it reads); and the case, the fragments, and the rules file with their hashes as
provenance. A lock is generated, never edited, byte-identical on every site; its SHA-256 is
the **file hash**, and the runner computes its **workload id**, the canonical resolved
values without the submission's required values and the storage-reported numbers, which
results are compared by.
