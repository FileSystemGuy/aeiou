## In brief

DCP load: every rank reads .metadata, then the items of its shard file (fan-in `replicas`). In the catalog it is `checkpointing/dcp-load`: application `torch-dcp`, format `dcp`, phase training, domain ai. Not yet decided between the two; the case's README says why (`four-items`: model-state data), its parameters holding at 2 GPUs. Not traced yet. It reads the objects of `ckpt`, each 72.0 MiB. It reads the objects of `ckpt_meta`, each 2 MiB. Each of the 2 `gpu` actors (one per GPU): in phase `restore`, on an object of `ckpt_meta`, open, fstat, ioctl TCGETS, lseek; twice: read 1 MiB; close; on an object of `ckpt`, open, fstat, ioctl TCGETS, lseek; 4 times: when `not head_in`, lseek; lseek; when `not head_in`, lseek; twice: lseek; when `not head_in`, read 1 MiB; twice: lseek; when `not end_in`, when `o + n > be`, lseek; lseek 4 times, read 1 MiB; when `far`, lseek; lseek; when `far`, read 1 MiB; when `last`, 6 times: lseek, read 1 MiB; 8 times: lseek; when `far or last`, lseek; lseek; when `far or last`, read 1 MiB; 5 times: lseek; when `far or last`, lseek; lseek; when `far or last`, read 1 MiB; 3 times: lseek; when `far and hdr + item_bytes[t] > buf`, read `hdr + item_bytes[t] − buf`, otherwise 21 times: lseek; close; a barrier with every GPU.
