that still gives these numbers within their tolerances, where `aeiou-catalog check` re-measures
them; where the seeds differ by more than a tolerance, the numbers carry that error and are named.
The numbers are the abstract's, not the trace's, and reuse grows with a run's length on a fixed
dataset: they describe the case at its length.

## Glossary

Every attribute and value a record may use (`attributes.toml`). Curated attributes are written in the
records, derived ones read from the AST and the captures, measured ones computed from the dry run.

### `category`

What the job is, the tree's first level. *(curated, mechanism, required)*

- `training`: A training job's input pipeline: samples read for steps on accelerators. *Also: dataloader, input pipeline.*
- `inference`: Serving a model: loading its weights. *Also: serving, model loading.*
- `checkpointing`: Saving and restoring a training job's state. *Also: checkpoint, restore, resume.*
- `vdb`: A vector database: building an index and searching it. *Also: vector search, ann, rag, retrieval.*
- `kvcache`: An inference engine's KV cache offloaded to storage and loaded back. *Also: kv cache, prefix cache, kv offload.*
- `synthetic`: A benchmark that is not an application (IO500 and the like): its defined operations, never a trace.

### `access`

How a training job's loader takes its samples, the tree's second level under training. *(curated, mechanism)*

- `map`: Map-style: each sample by its id, in a shuffled order without replacement. *Also: random access, map-style.*
- `stream`: Streaming: whole shards in a shuffled order, records taken in shard order. *Also: iterable, sharded, webdataset.*

### `application`

The library or program whose I/O the mechanism reproduces, as traced. *(curated, mechanism, required)*

- `pytorch-dataloader`: PyTorch's DataLoader with worker processes over a map-style Dataset. *Also: pytorch, torchvision.*
- `numpy`: NumPy's np.load of .npz archives.
- `h5py`: h5py over libhdf5.
- `tf-data`: TensorFlow's tf.data pipeline. *Also: tensorflow.*
- `pyarrow`: Apache Arrow's Parquet reader. *Also: arrow.*
- `torch-dcp`: torch.distributed.checkpoint (DCP), save and load. *Also: fsdp, pytorch.*
- `transformers-safetensors`: Hugging Face from_pretrained over safetensors shards. *Also: hugging face, huggingface.*
- `faiss`: FAISS (Meta).
- `diskann`: DiskANN (Microsoft), through diskannpy.
- `vllm-lmcache`: vLLM with LMCache's storage backends. *Also: vllm, lmcache.*

### `format`

How the data is laid out in files. *(curated, mechanism, required)*

- `file-per-sample`: One file per sample, read whole (JPEG and the like). *Also: jpeg, imagefolder, small files.*
- `npz`: One NumPy .npz archive per sample.
- `hdf5`: HDF5 containers of fixed-size rows.
- `tfrecord`: TFRecord shards of length-prefixed records.
- `parquet`: Parquet shards of row groups.
- `dcp`: DCP shard files (one per rank) and a .metadata file. *Also: distcp.*
- `safetensors`: safetensors shards: a JSON header and the tensors' bytes.
- `faiss-ivf-ondisk`: A FAISS index file and an inverted-lists file mapped whole.
- `diskann-index`: DiskANN's disk index of 4 KiB sectors, its PQ file, and build temporaries.
- `lmcache-chunks`: One file per KV chunk of a fixed number of tokens, named by prefix hash. *Also: kv chunks.*

### `kind`

What a case is for. *(curated, case, required)*

- `example`: An example case: a configuration small enough to trace, showing that the abstract issues the application's calls. Not a job anyone runs as a benchmark.
- `use`: A use case: a configuration describing a real job, valid at the GPU counts it declares.
- `unsettled`: Not yet decided between the two; the case's README says why.

### `modality`

What the job's data is, as its users name it. *(curated, case)*

- `image`: Still images. *Also: vision, cv.*
- `volume`: Dense arrays per sample (scientific volumes, tensors). *Also: scientific, 3d.*
- `text`: Conversations and documents, as tokens. *Also: chat, llm, nlp.*
- `agentic`: An agent's sessions: long contexts reused across many requests. *Also: agents, coding agent.*
- `vectors`: Embedding vectors. *Also: embeddings.*
- `model-state`: A model's weights or a training job's state. *Also: weights, optimizer state.*

### `api`

The API the abstract declares for its POSIX names (`posix` key; sync when it declares none), the S3 client's when it has object names. Another API is another workload (CLOSED). *(derived, case)*

- `sync`: Blocking system calls, one thread per actor.
- `mmap`: Mapped files: reads are page faults.
- `libaio`: Linux kernel AIO on O_DIRECT descriptors. *Also: aio, o_direct.*
- `posix-aio`: glibc's POSIX AIO.
- `io_uring`: io_uring.

### `writes`

Whether the abstract writes (declares an output namespace). *(derived, case)*

- `yes`: It writes files of its own.
- `no`: It only reads.

### `inputs`

Whether it reads what another run wrote (an `input` namespace). *(derived, case)*

- `yes`: It reads another run's output: a restore, a cold KV reader.
- `no`: It reads datasets and what it wrote itself.

### `status`

What the captures say: the best verdict of `aeiou-trace compare --judge` over the case's captures. *(derived, case)*

- `untraced`: No capture.
- `accepted`: A capture is within the tolerances.
- `not-accepted`: Captured, but rows are outside; each has its recorded reason.
- `nothing-judged`: Captured, but the trace cannot see the data path (a mapped file).

### `run_length_read`

Contiguous bytes read: the byte-weighted median of read run lengths (half the bytes read move in runs at least this long). *(measured, case)*

Stable within ±25 %.

- `large`: 32 MiB or more.
- `medium`: 1 MiB to 32 MiB.
- `small`: 16 KiB to 1 MiB.
- `tiny`: Under 16 KiB.

### `run_length_write`

Contiguous bytes written: the byte-weighted median of write run lengths. *(measured, case)*

Stable within ±25 %.

- `large`: 32 MiB or more.
- `medium`: 1 MiB to 32 MiB.
- `small`: 16 KiB to 1 MiB.
- `tiny`: Under 16 KiB.

### `request_size_read`

The byte-weighted median of read request sizes, as the application asks; a request larger than the file returns short. *(measured, case)*

Stable within ±25 %.

- `large`: 32 MiB or more.
- `medium`: 1 MiB to 32 MiB.
- `small`: 16 KiB to 1 MiB.
- `tiny`: Under 16 KiB.

### `request_size_write`

The byte-weighted median of write request sizes. *(measured, case)*

Stable within ±25 %.

- `large`: 32 MiB or more.
- `medium`: 1 MiB to 32 MiB.
- `small`: 16 KiB to 1 MiB.
- `tiny`: Under 16 KiB.

### `read_share`

Bytes read over bytes moved. *(measured, case)*

Stable within ±0.02.

- `write-only`: No reads.
- `read-only`: No writes.
- `read-mostly`: At least 80 % of the bytes read.
- `mixed`: 20 % to 80 % read.
- `write-mostly`: Under 20 % read.

### `metadata`

Metadata calls (open, close, stat, fstat, readdir, mkdir, rmdir, unlink, rename, ftruncate, fallocate) per data call (read, write). *(measured, case)*

Stable within ±5 % or ±0.005.

- `high`: Two or more per data call.
- `medium`: 0.5 to 2.
- `low`: 0.01 to 0.5.
- `none`: Under one in a hundred data calls.

### `reads_own_writes`

Whether any read follows a write of the same block (read after write). *(measured, case)*

- `yes`: Some reads read back what the run wrote.
- `no`: No read reads what the run wrote.

### `reread`

Block reads that read a block again, over all block reads. A training job's value is its epoch count's, a parameter. *(measured, case)*

Stable within ±0.02.

- `repeated`: Half the reads or more read a block again.
- `some`: 5 % to 50 %.
- `none`: Under 5 %.

### `skew`

The share of block accesses on the busiest 1 % of blocks. *(measured, case)*

Stable within ±0.02.

- `skewed`: 10 % or more of the accesses on 1 % of the blocks.
- `uniform`: Under 10 %.
