## In brief

One engine per actor; `concurrency` request slots; each request continues an earlier conversation or starts one. In the catalog it is `kvcache/lmcache-local-disk`: application `vllm-lmcache`, format `lmcache-chunks`, phase inference, domain ai. An example case (`sharegpt-chat`: text data, a llm model), its parameters holding at 1 GPU. Traced: a capture is within the tolerances. `sysp` holds 2 samples, stored as chunk objects (10.9 MiB in 4 files and 2 directories), looked up by id; sizes always 5.5 MiB (a lognormal clamped to it). `subp` holds 50 samples, stored as chunk objects (942.9 MiB in 338 files and 50 directories), looked up by id; sizes lognormal, median 17.6 MiB, σ 0.3 (5th–95th percentile 10.7 MiB to 28.8 MiB), clamped to at least 12 KiB and at most 1.1 GiB. It writes the objects of `kv`, each 3 MiB. The one `gpu` actor (one per GPU): 300 times: in phase `warm` while `r < warm`, else `serve`,, compute for `draw(think)`; `load` in parallel, each: open, fstat, ioctl TCGETS, lseek, read 3 MiB, close; for each `s` below `⌈(stored − had) / (prefill_step div chunk_tokens)⌉`: compute for `prefill_per_token × min((stored − had − s × (prefill_step div chunk_tokens)) × chunk_tokens, prefill_step)`; for each `k` below `min(stored, had + (s + 1) × (prefill_step div chunk_tokens))`: open for writing, fstat, ioctl TCGETS, lseek, write 3 MiB, close; compute for `decode_per_token × out`. Measured by dry run at 1 GPU (5,868 ops: 978 close, 978 fstat, 978 ioctl, 978 lseek, 978 open, 596 read, 382 write; 1.7 GiB read, 1.1 GiB written): read runs: medium (3 MiB); write runs: medium (3 MiB); read requests: medium (3 MiB); write requests: medium (3 MiB); share of bytes read: mixed (65.5%); metadata ops per data op: high (3); reads its own writes: yes; share of bytes read that are re-reads: repeated (62%); share of accessed bytes on the most accessed 1% of bytes: uniform (2.73%).
