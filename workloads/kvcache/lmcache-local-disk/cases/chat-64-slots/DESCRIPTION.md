## In brief

One engine per actor; `concurrency` request slots; each request continues an earlier conversation or starts one. In the catalog it is `kvcache/lmcache-local-disk`: application `vllm-lmcache`, format `lmcache-chunks`, phase inference, domain ai. Not traced yet. `sysp` holds 50 samples, stored as chunk objects (9.9 GiB in 342 files and 50 directories), looked up by id; sizes lognormal, median 187.5 MiB, σ 0.3 (5th–95th percentile 114.5 MiB to 307.1 MiB), clamped to at least 128 KiB and at most 12.2 GiB. `subp` holds 50 samples, stored as chunk objects (9.8 GiB in 338 files and 50 directories), looked up by id; sizes lognormal, median 187.5 MiB, σ 0.3 (5th–95th percentile 114.5 MiB to 307.1 MiB), clamped to at least 128 KiB and at most 12.2 GiB. It writes the objects of `kv`, each 32 MiB. The one `gpu` actor (one per GPU): 64 in parallel, each: 22,000 times: in phase `warm` while `r < warm`, else `serve`,, compute for `draw(think)`; `load` in parallel, each: open, fstat, ioctl TCGETS, lseek, read 32 MiB, close; for each `s` below `⌈(stored − had) / (prefill_step div chunk_tokens)⌉`: compute for `prefill_per_token × min((stored − had − s × (prefill_step div chunk_tokens)) × chunk_tokens, prefill_step)`; for each `k` below `min(stored, had + (s + 1) × (prefill_step div chunk_tokens))`: open for writing, fstat, ioctl TCGETS, lseek, write 32 MiB, close; compute for `decode_per_token × out`.
